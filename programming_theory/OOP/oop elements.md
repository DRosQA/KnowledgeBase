
## Class
template to create objects. Establishes a "is-A" relationship, i.e. all instances should be some kind of the class (a banana **is-A** fruit).
### subclass
class **inheriting** from another, parent class.
### parent class
class from which another class **inherits**
### base class
top-level class from which others inherit. A class without a parent. 
### abstract class
class that cannot be instantiated directly, only via subclasses.
### concrete class
non-abstract class. Class that can be instantiated.
## factory
class for creating objects. An **[[oop concepts|abstraction]]** of a **constructor** class

## Object 
representation of a thing in the software, an **instance** of a **class**. Holds state, behavior and identity.
### god object
object that has too many different things in it. A sign of badly-written code.
### parent object
object created from a parent class
### child object
object created from a subclass.

### Member variable
(**field, property, attribute**)
variable associated with an object/class.
#### class variable 
variable that belongs to class.
#### instance variable 
variable that belongs to object.


## Function
definition of behavior that can be called upon. Callable piece of code.
### method
function that belongs to a class.
### abstract method
method that only has a declaration and no body, and subclasses are required to implement it themselves.

## Interface
entry-point for interaction between pieces of code. A contract defining what information will be exchanged

### Instance
element created from a base template.

### Constructor
(initializer)
function which is used to create an object.

## Component
self-contained piece of code that can be re-used easily. Establishes a "has-A" relationship (an animal **has** legs). See [[oop concepts|encapsulation]].

## Container
class which's purpose is to hold objects rather than provide new functionality.
